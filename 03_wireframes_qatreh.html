صف کارها با Redis و Celery

🎯

هدف امروز: یک کار سنگین را از مسیر درخواست جدا کنی و در پس‌زمینه اجرا کنی.

۱) چرا صف کار لازم داریم؟

اگر ارسال ایمیل یا پردازش تصویر داخل مسیر درخواست اجرا شود، کاربر باید منتظر بماند و یک خطای ساده، کل درخواست را می‌خواباند. راه‌حل استاندارد: درخواست را در صف بگذار و پاسخ فوری برگردان.

# app/tasks.py — تعریف کار پس‌زمینه from celery import Celery app = Celery("drip", broker="redis://localhost:6379/0") @app.task def send_daily_lesson(chat_id: str, day: int): # ارسال خلاصه درس در روبیکا ...
⚡

نکته طلایی: هر کاری که بیش از ۵۰۰ میلی‌ثانیه طول بکشد، از مسیر درخواست بیرون است — حتی اگر «الان کار می‌کند».

۲) انتخاب صف مناسب

Redis برای صف‌های سبک و پرتعداد، RabbitMQ برای مسیرهای حساس. برای این دوره Redis کافی است؛ دلیل انتخاب را در دفترچه تصمیم‌ها ثبت کن.

نمودار: درخواست → صف → Worker → نتیجه

🏋️ تمرین امروز ۳۵ دقیقه

فعلاً ذخیره‌نشده

صورت تمرین: یک صف Redis بساز، سه کار نمونه به آن بفرست و با یک Worker اجرا کن. زمان اجرای هر کار را لاگ بگیر.

خروجی مورد انتظار: فایل tasks.py + اسکرین‌شات لاگ + یک خط توضیح از آنچه یاد گرفتی.
